I need you to design and build a production-quality LOCAL LIVE SCOREBOARD SYSTEM

12. UNDO SYSTEM
==================================================

Undo is extremely important.

Every scoring action must create a history entry.

Example:

RUN_ADD +1
BALL_ADD +1

OUT_ADD +1

UNDO must restore the exact previous state.

RECENT ACTIONS

+1 Run
+1 Ball
+4 Runs
+1 Out

Provide:

UNDO LAST ACTION

Do not implement Undo by guessing values.

Store previous snapshots or reversible events.

15. REAL-TIME SYNCHRONIZATION
==================================================

Use:

BroadcastChannel API

Create a channel such as:

belihuloya-scoreboard

When admin changes state:

Admin
→ update Zustand/store
→ save state to localStorage
→ broadcast full authoritative match state
→ Overlay receives state
→ Overlay renders immediately

The overlay must not maintain separate scoring logic.

Admin is the source of truth.

Broadcast a complete state snapshot rather than many unrelated messages.

Example event:

{
  type: "MATCH_STATE_UPDATED",
  payload: {
    teamA: ...,
    teamB: ...,
    battingTeam: ...,
    runs: 8,
    balls: 20,
    outs: 1,
    status: "LIVE"
  }
}

29. ERROR RECOVERY
==================================================

Design recovery procedures.

CASE:
Admin accidentally refreshes.

Expected:
state restores from localStorage.

CASE:
OBS Browser Source reloads.

Expected:
overlay reads stored state and continues.

CASE:
OBS crashes.

Expected:
after reopening OBS and local scoreboard,
last saved score is restored.

CASE:
operator enters wrong score.

Expected:
use Undo.

CASE:
internet disconnects.

Expected:
scoreboard and OBS continue locally.
Facebook connection may stop/reconnect,
but score state must remain intact.

CASE:
logo fails to load.

Expected:
show safe placeholder but never break entire overlay.
